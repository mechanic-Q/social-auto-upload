# 创作活动：CLI 接口统一，实现分散在各发布通道

快手与头条都要"发布时参与创作活动"和"活动发现"能力，但两平台发布页的活动 UI 毫无共性。我们决定：对外接口统一——CLI 提供 `--activity "活动名"`（发布时参与）与 `sau <平台> list-activities`（活动发现，输出 JSON 供 agent 消费），而页面交互逻辑由各 uploader（发布通道）自行实现，不抽象公共基类。这样 agent pipeline 无需关心平台差异；一旦平台改版只需改对应 uploader。代价是各实现间可能出现行为细节不一致（如活动名匹配策略），靠文档与测试约束而非代码约束。

## Considered Options

- 各平台独立参数（`--ks-activity` 等）：调用方被迫处理平台差异，pipeline 复制粘贴成本高。
- 跨平台公共"活动模块"基类：当时仅两个平台且 UI 无共性，抽象属于猜测性设计，改版时公共层反而成为约束。

## Consequences

新增平台要支持活动时，实现 `--activity` 匹配与 `list-activities` 是该平台接入清单的一部分，而不是可选项。
